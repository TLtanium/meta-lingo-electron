>   Noisy = too many near-duplicate topics, generic/uninformative topic words, poor coherence.

>      e.g. 'GROWTH is consistently framed within a discourse prosody of urgency and scarcity
>      (pressured, constrained, urgent, critical)'
>   3. If the prosody is ambiguous or split, note both orientations and flag for concordance follow-up.
> Format:
>   📎 Discourse Prosody: [name] — [1 sentence description of evaluative orientation,
>      citing 3–5 specific collocates as evidence]
>   OR
>   📎 Discourse Prosody: ambiguous — [describe the split, flag for concordance analysis]
>
> === DMIP CONTEXT PROFILE (REQUIRED BEFORE ANY DMIP ANALYSIS) ===
> Before beginning Step 1 of DMIP for ANY text, construct a Discourse Context Profile:
>
>   [PRODUCER — primary variables, anchor for DR/IR judgment]
>   INSTITUTIONAL SPEAKER: Who is the producing institution and what is their communicative role?
>   COMMUNICATIVE PURPOSE: What is the speaker trying to achieve?
>   GENRE: What is this text type and what conventions govern it?
>
>   [AUDIENCE — secondary variables, calibrate the qualified reader test]
>   INTENDED AUDIENCE: Who is the qualified original reader?
>   DOMINANT REGISTER: formal / semi-formal / promotional / technical
>
> State this profile once at the top of the DMIP report under ## Discourse Context Profile
> (before the MRW table).
>
> THEORETICAL ANCHOR: Deliberateness is a property of the PRODUCER, not the reader.
> The qualified original reader test is a DIAGNOSTIC TOOL to infer producer intent.
>
> CRITICAL RULE FOR DR/IR: Ask 'Would this producer, in this communicative situation and genre,
> intend for the source domain to enter the intended audience's situation model?'
>   → Same MRW can be IR if produced routinely (no intent to activate source domain)
>   → Same MRW can be DR if producer elsewhere develops the same source domain (extended metaphor)
>   → Deciding variable is PRODUCER INTENT, diagnosed via qualified reader as proxy.
>
> === DELIBERATE METAPHOR ANALYSIS (DMIP) ===
> When user asks for deliberate metaphor / DMIP analysis on a corpus:
>   1. get_corpus_info(corpus_id) → list all texts.
>   2. For EACH text: call dmip_analysis(corpus_id, text_id).
>      → This returns the full MIPVU-annotated text + the embedded DMIP procedure.
>   3. Apply the embedded DMIP procedure to each MRW in that text.
>      ZERO-SHOT: base all judgments on the specific text and your own linguistic
>      knowledge — do not pattern-match to examples or analogies.
>   4. Output per-text DMIP report using the DMIP template above.
>   5. After all texts: write a cross-text summary of deliberate metaphor patterns.
> KEY RULES:
>   Referential dimension is the gateway criterion:
>   DR (Direct Reference) = source domain enters the reader's situation model → potentially deliberate.
>   IR (Indirect Reference) = lexical disambiguation only; no mental scene → NON-DELIBERATE. Stop.
>   CONVENTIONAL DEFAULT: if CONVENTIONAL + isolated (no MFLAG, no confirmed extended cluster)
>     → default IR unless specific textual evidence shows source domain reactivation.
>   CONVENTIONALITY CHECK (Dimension 2): a word's contextual/figurative meaning is
>     CONVENTIONAL if it is itself a separately-listed sense in a general dictionary —
>     NOT whether the word feels well-chosen in this text. When uncertain, call
>     dictionary_lookup(word): a matching numbered sense (麦克米伦/Macmillan) or a
>     matching listed collocation (朗文搭配/Longman Collocations) → CONVENTIONAL; cite
>     it in the Evidence field. Do not let the Step 1 genre framing override this.
>   COUNTERFACTUAL TEST (before any DR verdict): 'Can a non-specialist reader fully understand
>     this word without invoking the source domain?' YES → IR/WIDLII. NO → DR may apply.
>   EXTENDED METAPHOR requires ALL THREE: (a) ≥3 MRWs from same concrete source domain,
>     (b) within 5 sentences, (c) building a coherent source-domain scene together.
>   SECOND PASS (Step 6): after completing all MRW judgments, re-examine every PD verdict
>     against the counterfactual test and extended metaphor criteria; record any revisions.
>   When in doubt → WIDLII: label POTENTIALLY DELIBERATE and flag uncertainty.

### 3.4 `concordance.py`


#### `concordance_search`


> Search for words/phrases in context (KWIC - Key Word In Context).
>
> When to use: Qualitative inspection of usage, concordance lines, or CQL-based
> pattern search. First-line tool for examples and discourse patterns.
>
> Shows each occurrence with surrounding context, essential for
> understanding how words are used in actual texts.
>
> Search modes:
> - "exact": exact word match
> - "contains": word contains the query
> - "starts": word starts with query
> - "ends": word ends with query
> - "phrase": exact phrase match
> - "wordlist": multiple words (one per line in query)
> - "cql": Corpus Query Language for complex pattern queries
>
> CQL Quick Reference (use with search_mode="cql"):
>   [word="run"]                     - exact word match
>   [lemma="run"]                    - any form (runs, running, ran)
>   [pos="NOUN"]                     - any noun
>   [pos="ADJ"][pos="NOUN"]          - adjective followed by noun
>   [word="the" & pos="DET"]         - "the" as determiner (AND)
>   [pos="NOUN" | pos="VERB"]        - noun or verb (OR)
>   [!pos="PUNCT"]                   - not punctuation (NOT)
>   [pos="VERB"][]{0,3}[pos="NOUN"]  - verb, then 0-3 any words, then noun
>   []                               - any single token
>   []{2,4}                           - 2 to 4 any tokens
>   [dep="nsubj"]                    - subject dependency relation
>   [usas="A1.1"]                    - USAS semantic domain A1.1
>   [headword="make"]               - token whose head word is "make"
>   [headpos="VERB"]                 - token whose head is a VERB
>   <s> [pos="DET"] </s>            - within sentence boundary
>
>   Supported attributes: word, lemma, pos (Universal), tag (Penn),
>     dep, usas, nrc, headword, headlemma, headpos, headdep
>   Operators: & (AND), | (OR), ! (NOT)
>
>   TIP: Use validate_cql(query) first to check syntax before searching.
>
> Sorting options:
> - sort_by: primary sort criterion
>   "left_context" / "right_context" - alphabetical by context
>   "position" - by position in text
>   "frequency" - by frequency of keyword
>   "random" - random order
> - sort_levels: multi-level context sorting keys
>   e.g. ["1L", "2L"] = sort by 1st word left, then 2nd word left
>   Format: "{n}L" or "{n}R" where n=word position, L=left, R=right
>
> Args:
>     corpus_id: Corpus ID to search
>     query: Search query (word, phrase, or CQL expression)
>     text_ids: Specific text IDs (None = all)
>     search_mode: "exact", "contains", "starts", "ends", "phrase",
>                  "wordlist", or "cql"
>     search_target: What to match: "word" or "lemma"
>     ignore_case: Case-insensitive matching (default: true)
>     context_size: Number of context tokens on each side (default: 5)
>     sort_by: Sort criterion (see above, default: None)
>     sort_levels: Multi-level sort keys (see above, default: None)
>     sort_descending: Descending sort order (default: false)
>     pos_filter: Filter results by POS tags, e.g. ["NOUN", "VERB"]
>     max_results: Hard cap on results from backend (default: None)
>     limit: Max results to display (default: 30)
>     save_path: Save results as CSV. Path, directory, or empty string for ~/Downloads. None = don't save.

### 3.6 `dmip.py`


#### `dmip_analysis`


> Prepare a full DMIP (Deliberate Metaphor Identification Procedure) analysis
> context for a single text in a corpus.
>
> When to use: When asked to identify DELIBERATELY used metaphors in a text,
> or to apply DMIP / Deliberate Metaphor Theory (DMT) analysis. This tool
> retrieves the text's MIPVU-annotated content and presents it alongside the
> complete DMIP four-dimension analysis procedure so you can reason about
> each metaphor-related word (MRW) and judge whether it is POTENTIALLY
> DELIBERATE or NON-DELIBERATE.
>
> The tool:
>   1. Fetches the full text content from the corpus
>   2. Retrieves the MIPVU annotation (sentences + per-token metaphor labels)
>   3. Reconstructs the text with inline MIPVU markers:
>        [MET:word]   indirect metaphor (contextual ≠ basic meaning)
>        [DIR:word]   direct metaphor (literally used; introduces source domain)
>        [MFLAG:word] metaphor flag/marker (like / as / as if / resemble / etc.)
>        [IMPL:word]  implicit metaphor (references prior MRW via cohesion)
>   4. Lists all MRWs sentence by sentence
>   5. Provides the complete DMIP four-dimension analysis instructions
>
> After calling this tool, analyze each MRW using the DMIP procedure and output
> a structured four-dimension judgment (Linguistic, Conceptual, Referential,
> Communicative) with evidence for each POTENTIALLY DELIBERATE verdict.
>
> Args:
>     corpus_id: Corpus ID containing the text
>     text_id: Text ID (from get_corpus_info)
>     include_implicit: Include implicit metaphors in MRW list (default: True)

#### `dictionary_lookup`


> Look up a word in Meta-Lingo's built-in dictionaries.
>
> When to use: For DMIP Dimension 2 (CONVENTIONAL vs NOVEL) judgments — to
> ground the conventionality call in an external lexicographic resource

>   - LISTED as a numbered sense → CONVENTIONAL (lexicalized), even if the
>     word feels well-chosen or evocative in this text. A skillful writer's

>     being NOVEL.

>     in this context → NOVEL.

>     including figurative/extended senses (~66,700 headwords).

>     (typical adjectives/verbs/prepositions for a headword) for ~4,200
>     common headwords.

>     word: Word or lemma to look up (case-insensitive).
>     dictionaries: Dictionary names to query. Default: both
>         ["麦克米伦", "朗文搭配"].

>         (default 4000). Highly polysemous words (e.g. "make", "set",

#### `metaphor_analysis`


> Analyze metaphor usage in the corpus using MIPVU methodology.
>
> When to use: Metaphor density and distribution of metaphor-related words (MRWs)
> via the MIPVU pipeline. English-focused; ensure MIPVU annotation has completed.
>
> MIPVU classifies each word token into one of these types:
>   INDIRECT  — word used metaphorically (contextual ≠ basic meaning); majority of MRWs
>   DIRECT    — word used literally but introduces an incongruous source domain (simile target)
>   MFLAG     — explicit metaphor signal (like / as / as if / imagine / resembles / etc.)

>   literal   — non-metaphorical (is_metaphor=False); included so word frequency is visible
>
> Source types in results (all from the same metalingo-indirect-metaphor model):
>   filter    = excluded by word-form filter (NOT metaphorical)
>   rule      = MIPVU SpaCy rule-based detection
>   finetuned = DeBERTa model output, function word (IN/DT/RB/RP) — orange in UI
>   clause    = DeBERTa model output, content word (VERB/NOUN/ADJ/…) — green in UI
>   (hitz     = legacy label in old annotations, treated same as clause)
>
> Args:
>     corpus_id: Corpus ID to analyze
>     text_ids: Specific text IDs (None = all texts in corpus)
>     result_mode: "word" (default) for word-level ranked table; "source" for by-source summary
>     pos_filter: Filter by Universal POS, e.g. ["NOUN", "VERB", "ADJ", "ADV", "ADP", "DET"]
>     search_word: Filter by word/lemma pattern
>     search_type: Match type: "exact" | "contains" | "starts" | "ends" | "regex"
>     search_target: Search in: "word" (wordform) or "lemma"
>     min_freq: Minimum frequency (default 0 = no minimum)
>     max_freq: Maximum frequency (0 = no limit)
>     include_implicit: When True, implicit metaphors are resolved to their antecedent MRW,
>                       and an implicit_ref_count (+N) is added to that antecedent's frequency
>                       display. Default False (implicit metaphors shown as separate rows).

### 3.11 `task.py`


#### `plan_analysis_task`


> Create a structured analysis plan and start a multi-text task.
>
> WHEN TO USE: Any time you need to analyze MORE THAN 3 TEXTS.
> Call this BEFORE beginning per-text analysis — it fixes the plan.
>
> WORKFLOW AFTER CALLING THIS:
>   For EACH text in the plan (in order):
>     1. Run analysis tool(s) for the declared dimensions
>     2. save_text_result(task_id, text_id, label, content, status='success')
>        → On error: status='failed', error_message='<reason>', content=''
>        → On retry success: status='success', content=<full analysis>
>     3. Acknowledge "✓ [k/N] label — saved" only; do NOT repeat the analysis
>   After ALL texts (including failed ones):
>     read_task_results(task_id)   → write cross-text aggregation
>
> FAULT TOLERANCE:
>   - First failure: retry once with the same analysis tool call
>   - Retry still fails: save_text_result(..., status='failed', error_message='…')
>     and continue with the next text — do NOT abort the whole task
>   - All failed/skipped texts are reported together at the end of aggregation
>
> EXECUTION ORDER:
>   "sequential" (default): process one text at a time
>   "parallel": batch multiple texts' tool calls in a single message so they
>     execute concurrently. Only use when texts are independent and the
>     analysis tool is lightweight (e.g., concordance, word frequency per text).
>
> PLAN TEXT FORMAT (texts arg):
>   Each entry must be: {"text_id": "...", "label": "..."}
>   Obtain from get_corpus_info(corpus_id) → texts list.
>
> ANALYSIS DIMENSIONS:
>   Declare what you will analyze per text, e.g.:
>   ["metaphor", "stance_markers", "topic_distribution"]
>   These are recorded in the plan for reference; they do not restrict tool calls.
>
> Args:
>     corpus_id: The corpus being analyzed
>     task_type: Short label, e.g. "dmip", "metaphor", "stance", "multi"
>     texts: Ordered list of {"text_id": "...", "label": "..."}

### 3.12 `topic.py`


#### `topic_modeling`


> Run topic modeling (LDA, LSA, or NMF) on a corpus.
>
> When to use: Unsupervised thematic structure discovery in texts.
> For BERTopic (neural/semantic), use: create_bertopic_embedding → bertopic_analyze.
>
> IMPORTANT: May take 30-120 seconds depending on corpus size and method.
>
> Methods:
> - "lda": Latent Dirichlet Allocation (Gensim, probabilistic) — best for large corpora
> - "lsa": Latent Semantic Analysis (TruncatedSVD, linear) — fast, good for medium corpora
> - "nmf": Non-negative Matrix Factorization — sparse, interpretable topics
>
> === DIAGNOSING BAD RESULTS AND HOW TO FIX THEM ===
>
> Problem: Topics look too similar / overlap heavily
> → Fix (LDA): Increase lda_passes (e.g. 20-30), set lda_alpha="asymmetric"
> → Fix (NMF): Try nmf_init="nndsvda", increase nmf_max_iter (e.g. 500)
> → Fix (all): Reduce n_topics, increase lda_min_df/lsa_min_df/nmf_min_df
>
> Problem: Topics dominated by generic/uninformative words
> → Fix: Ensure remove_stopwords=True, increase min_word_length (e.g. 3-4)
>        Increase lda_min_df/nmf_min_df to 3-5 to remove rare noise words
>        Use pos_filter=["NOUN", "VERB"] with pos_keep_mode=True for content words only
>
> Problem: Incoherent topics with random-looking words
> → Fix (LDA): Increase lda_passes (e.g. 15-20), increase lda_iterations (e.g. 100)
> → Fix (LDA): Try lda_alpha="asymmetric" for sparser topic distributions
> → Fix (all): Reduce n_topics (fewer but more coherent topics)
>
> Problem: Too many near-empty topics (very few keywords or docs)
> → Fix: Reduce n_topics, increase lda_min_df/lsa_min_df/nmf_min_df
>        For LDA: increase lda_minimum_probability (e.g. 0.05)
>
> Problem: Small corpus (< 50 documents), unstable results
> → Fix (LDA): lda_min_df=1, lda_passes=20, n_topics=3-5, lda_alpha="asymmetric"
> → Fix (NMF): nmf_init="random", nmf_random_state=42, n_topics=3-5
> → Consider: LDA or NMF usually beats LSA on very small corpora
>
> === STRATEGY: AUTO-ADJUST BASED ON RESULTS ===
> After seeing results, you should:
> 1. If topics overlap → rerun with fewer n_topics or higher min_df
> 2. If topics are incoherent → rerun with more lda_passes or pos_filter on nouns
> 3. If results vary run to run → set a fixed random_state and increase passes
> 4. Always try 2-3 different n_topics values (e.g. 5, 8, 12) and compare
>
> Args:
>     corpus_id: Corpus ID to analyze
>     text_ids: Specific text IDs (None = all)
>     method: "lda", "lsa", or "nmf"
>     language: "english" or "chinese"
>     n_topics: Number of topics to discover (default: 10).
>               For small corpora (<50 docs) use 3-6.
>               For medium corpora (50-500 docs) use 6-15.
>     n_top_words: Top keywords per topic to show (default: 10)
>
>     Preprocessing:
>     remove_stopwords: Remove common stopwords (default: true)
>     remove_punctuation: Remove punctuation tokens (default: false)
>     lemmatize: Use lemma forms (default: true)
>     lowercase: Convert to lowercase (default: true)
>     min_word_length: Minimum word length (default: 2)
>     pos_filter: POS tags to filter (default: PUNCT/SYM/X/NUM/INTJ excluded)
>     pos_keep_mode: True=keep only listed POS, False=exclude listed POS (default: false)
>     ngram_enabled: Enable n-gram features (default: false)
>     ngram_n_values: N-gram sizes e.g. [2, 3] (default: [2])
>
>     LDA-specific (used when method="lda"):
>     lda_passes: Training passes over corpus (default: 10)
>     lda_iterations: Max iterations per document (default: 50)
>     lda_chunksize: Documents per chunk (default: 2000)
>     lda_update_every: Update model every N chunks (default: 1)

>     lda_alpha: Document-topic prior: "auto", "symmetric", "asymmetric" (default: "auto")
>     lda_eta: Topic-word prior: "auto", "symmetric" (default: "auto")
>     lda_min_df: Min document frequency for vocabulary (default: 2)

>

>     lsa_max_features: Max vocabulary size (default: 10000)
>     lsa_min_df: Min document frequency (default: 2)
>     lsa_max_df: Max document frequency fraction (default: 0.95)
>     lsa_tol: Tolerance for arpack (default: 0.0)
>     lsa_n_iter: Iterations for randomized SVD (default: 5)
>     lsa_n_oversamples: Oversampling for randomized SVD (default: 10)
>     lsa_power_iteration_normalizer: "auto", "QR", "LU", "none" (default: "auto")

#### `create_bertopic_embedding`


> Create sentence embeddings for BERTopic analysis (Step 1 of 2).
>
> When to use: Before bertopic_analyze(). Preprocessing + embedding can take
> 1-5 minutes depending on corpus size. The embedding is saved and reusable.
>
> After this completes, call bertopic_analyze(embedding_id) to discover topics.

> 1. create_bertopic_embedding(corpus_id) → get embedding_id

#### `bertopic_analyze`


> Run BERTopic analysis on an existing embedding (Step 2 of 2).
>
> When to use: After create_bertopic_embedding() completes. Uses the saved
> embedding to discover topics via UMAP + HDBSCAN + c-TF-IDF.
>
> === DIAGNOSING BAD RESULTS AND HOW TO FIX THEM ===
>
> Problem: Topic -1 has too many documents (outliers dominate)
> → Cause: hdbscan_min_cluster_size too large, most docs can't form clusters
> → Fix: Decrease hdbscan_min_cluster_size (e.g. 3–5 for small corpora)
>        AND/OR set reduce_outliers=True, outlier_strategy="distributions"
>
> Problem: All topic weights are 0.000 / doc counts far exceed actual texts
> → Cause: Embedding was created with chunking_enabled=True, inflating doc count
> → Fix: Re-create embedding with chunking_enabled=False (unless texts are very long)
>        Then re-run this analysis
>
> Problem: Too many topics (topic fragmentation), e.g. person-name clusters
> → Fix A: Increase hdbscan_min_cluster_size (e.g. 15–30)
> → Fix B: Set nr_topics=N to merge down to N meaningful topics after clustering
> → Fix C: Set vectorizer_min_df=3 or higher to suppress rare/noisy words
>
> Problem: Too few topics (everything lumped together)
> → Fix: Decrease hdbscan_min_cluster_size (e.g. 3–5)
>        AND decrease umap_n_neighbors (e.g. 5–8) for more local structure
>
> Problem: Topics look incoherent / generic words dominate
> → Fix: Increase vectorizer_min_df (e.g. 3–5) and vectorizer_max_df (e.g. 0.8)
>        Use representation_model="MaximalMarginalRelevance" for diverse keywords
>
> NOTE: umap_n_neighbors and umap_n_components are auto-adjusted on the server
> to stay below n_docs, so small corpora will not fail with "n_neighbors >= n_samples".
>
> === SMALL CORPUS RECIPE (< 100 texts) ===
> umap_n_neighbors=5, umap_n_components=3, hdbscan_min_cluster_size=3,
> hdbscan_min_samples=1, vectorizer_min_df=1, reduce_outliers=True
>
> === MEDIUM CORPUS RECIPE (100–1000 texts) ===
> umap_n_neighbors=10, umap_n_components=5, hdbscan_min_cluster_size=10,
> vectorizer_min_df=2 (defaults mostly fine)
>
> Args:
>     embedding_id: Embedding ID from create_bertopic_embedding or list_bertopic_embeddings
>     language: "english" or "chinese" (for tokenization)
>     n_top_words: Top words per topic to show (default: 10)
>

>                Use "auto" is NOT supported here; pass an integer or None.
>
>     Dimensionality reduction (UMAP):

>                       For small corpora use 5–8. Must be < number of documents.
>     umap_n_components: Output dimensions (default: 5; use 3 for very small corpora)
>     umap_min_dist: Min distance between projected points (default: 0.0)

>     umap_random_state: Random seed (default: 42)

>     cluster_method: "HDBSCAN" or "K-Means" (default: "HDBSCAN")
>     hdbscan_min_cluster_size: Min docs per topic cluster (default: 10).
>                               KEY PARAMETER — lower=more topics, higher=fewer topics.

>     hdbscan_min_samples: Controls noise sensitivity (None=auto; 1=least noise; default: None)
>                          Set to 1 for small corpora to minimize outliers.
>     hdbscan_metric: Distance metric: "euclidean" (default)

>     vectorizer_type: "CountVectorizer" or "OnlineCountVectorizer" (default: "CountVectorizer")
>     vectorizer_min_df: Min document frequency for vocabulary (default: 2).
>                        Increase to 3–5 to suppress rare noisy words (person names, typos).

>     vectorizer_ngram_range: N-gram range e.g. [1,2] for bigrams (default: [1,1])

>     vectorizer_exclusion_words: Extra words to exclude from vocabulary e.g. ["the","said"].

## 4. DMIP Embedded Procedure (`tools/dmip.py`)

The `_DMIP_PROCEDURE` constant is appended to every `dmip_analysis` tool output.
It embeds the full DMIP four-dimension analysis framework directly into the model context.


> ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
> DELIBERATE METAPHOR IDENTIFICATION PROCEDURE (DMIP)
> Based on Deliberate Metaphor Theory (Steen 2023) and Reijnierse et al. (2018)
> ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
>
> THEORETICAL FOUNDATION:
> A metaphor is POTENTIALLY DELIBERATE when the speaker intentionally invites the
> addressee to adopt the SOURCE DOMAIN as an ALIEN PERSPECTIVE through which to
> understand the target domain. This requires ONLINE CROSS-DOMAIN MAPPING, not
> mere lexical disambiguation.
>
> Non-deliberate metaphors (the vast majority of MIPVU-identified MRWs) are resolved
> by lexical disambiguation — the brain accesses the figurative meaning directly, with
> no source-domain scene constructed in the reader's situation model.
>
> ZERO-SHOT APPROACH: Apply all criteria below using your own linguistic judgment of
> the specific text in front of you. Do not pattern-match to analogies or pre-loaded
> examples — every discourse context is unique, and domain-specific examples introduce
> systematic bias toward false positives.
>
> FOUR-DIMENSION ANALYSIS MODEL:
>
> DIMENSION 1 – LINGUISTIC
>   Observe the surface form of the MRW:
>   • DIRECT: word used literally but introduces incongruous source domain;
>     often accompanied by MFLAG (like/as/as if/imagine/resemble/etc.)
>     → MFLAG present = strongest surface-level deliberateness signal
>   • INDIRECT: word used metaphorically (contextual ≠ basic meaning);
>     no explicit comparison marker
>   → Note: absence of MFLAG does not mean non-deliberate
>
> DIMENSION 2 – CONCEPTUAL
>   Evaluate the mapping between source and target domains:
>   • NOVEL: unexpected, creative connection requiring active construction
>     → strong deliberateness signal (cannot be resolved by lexical disambiguation)
>   • CONVENTIONAL: routine, lexicalized, processed automatically
>
>   CONVENTIONALITY TEST (anchor to the lexicon, not to "this text" — works for
>   any genre/domain):
>   Ask: is the word's CONTEXTUAL (figurative) meaning itself an established sense
>   already listed in a general-purpose dictionary as a separate numbered sense
>   (e.g. Macmillan), or a recognized fixed collocation (e.g. in a collocations
>   dictionary) — i.e. has this cross-domain mapping already become part of the
>   word's normal polysemy ("dead"/"sleeping" metaphor)?
>     YES → CONVENTIONAL, even if the word feels evocative or particularly
>           well-chosen in this text. A writer's CHOICE of a conventional word is
>           NOT the same question as whether the word's mapping is NOVEL.
>     NO  → the reader must construct this cross-domain mapping fresh, on the spot,
>           from the word's basic sense → NOVEL.
>   When uncertain, call dictionary_lookup(word) — if the contextual sense matches
>   a listed numbered sense (麦克米伦/Macmillan) or the phrase matches a listed
>   collocation (朗文搭配/Longman Collocations), treat as CONVENTIONAL and cite the
>   matching sense/collocation in the Evidence field.
>   This test depends only on the word's status in the general lexicon — NOT on the
>   text's subject matter, register, or rhetorical density.
>   ⚠ Do NOT let the Step 1 discourse/genre framing pre-determine this judgment:
>   characterizing a text as "rhetorically dense" or "strategic" does not make its
>   conventional words NOVEL.
>
>   CONVENTIONAL DEFAULT RULE:
>   If Dimension 2 = CONVENTIONAL and the MRW appears in isolation
>   (no MFLAG; not confirmed as part of an extended metaphor cluster — see criteria below),
>   the default judgment is IR unless there is specific, observable textual evidence
>   that the source domain is reactivated in this context.
>   The ability to construct a plausible source-domain scenario does NOT constitute
>   reactivation — only evidence that the original reader would construct it without
>   analytical prompting.
>
> DIMENSION 3 – REFERENTIAL (CORE DMIP CRITERION)
>   Ask: does the source domain entity enter the reader's SITUATION MODEL?
>
>   DIRECT REFERENCE (DR): A competent, qualified original reader of this text —
>     not a linguist performing analysis, but someone sharing the discourse
>     community's knowledge — would construct a mental scene in which the source
>     domain entity ACTUALLY EXISTS as a referent in the situation model.
>
>   INDIRECT REFERENCE (IR): Source domain dissolves into lexical meaning.
>     No scene is constructed. No alien perspective is activated.
>
>   RULE: Only MRWs with DR can be POTENTIALLY DELIBERATE.
>   IR → NON-DELIBERATE (stop analysis here).
>
>   ⚠ RESEARCHER ACTIVATION WARNING + COUNTERFACTUAL TEST:
>   Before labeling any MRW as DR, apply the counterfactual test:
>     "Without invoking the source domain, can a non-specialist reader of this text
>     fully understand what this word contributes to the sentence meaning?"
>     YES → The source domain is not entering the situation model.
>           Default to IR or WIDLII. Do not label DR.
>     NO  → The reader genuinely needs the source domain to decode the word's
>           contribution to meaning → DR may be justified.
>   This test operationalizes the distinction between analyst activation
>   (you can imagine the source domain) and reader activation (the reader
>   must engage with it to understand the sentence).
>
> DIMENSION 4 – COMMUNICATIVE
>   Is there textual evidence that the speaker INTENTIONALLY activated the source
>   domain as an alien perspective?
>   Consider: genre, register, speaker identity, discourse purpose, audience,
>   communicative situation.
>
> DISCOURSE-LEVEL FEATURES (shape deliberateness judgment):
>
>   • EXTENDED METAPHOR — STRONGEST signal of deliberateness.
>     Minimum requirements (ALL THREE must be satisfied):
>     (a) ≥3 MRWs traceable to the SAME CONCRETE source domain
>         (not a broad thematic category that subsumes multiple distinct sub-domains)
>     (b) occurring within 5 sentences of each other in the text
>     (c) jointly constructing a coherent, identifiable source-domain scene
>     A loose cluster of related-but-distinct sub-domains does NOT qualify
>     as an extended metaphor — each contributing MRW must share the same
>     concrete domain.
>     ▸ A conventional MRW becomes potentially deliberate ONLY when it is part
>       of a cluster meeting all three criteria above.
>
>   • HIGH-LEVEL LIMITED: MRW occupies MAIN PREDICATE position of an utterance
>     → strong deliberateness signal.
>
>   • LOW-LEVEL LIMITED: MRW in modifier/adjunct position
>     → weaker signal; likely conventional and non-deliberate.
>
>   • EMBEDDED: MRW nested inside another metaphor
>     → generally secondary; weaker deliberateness signal.
>
>   • WORDPLAY: MRW simultaneously activates two semantic domains via phonetic
>     similarity, punning, or deliberate polysemy → ALWAYS deliberate.
>
> DECISION PROCEDURE (follow these steps for each MRW):
>
>   Step 1: Read the FULL TEXT — establish the context model.
>     Who speaks? To whom? In what genre/situation? For what communicative purpose?
>
>   Step 2: For this MRW, identify the SOURCE DOMAIN.
>
>   Step 3: CONVENTIONAL DEFAULT CHECK
>     Is Dimension 2 = CONVENTIONAL and the MRW isolated (no MFLAG, no confirmed
>     extended metaphor cluster meeting all three criteria)?
>     YES → Default to IR unless Step 4's counterfactual test shows the reader
>           genuinely needs the source domain to understand the sentence.
>     NO  → Proceed normally through Steps 4–5.
>
>   Step 4: REFERENTIAL TEST + COUNTERFACTUAL TEST
>     Apply counterfactual: "Without invoking the source domain, can a non-specialist
>     reader fully understand this word's contribution to the sentence?"
>     YES → IR. Label NON-DELIBERATE. Stop.
>     NO  → Source domain is necessary for comprehension → DR. Proceed to Step 5.
>     UNCERTAIN → WIDLII. Label POTENTIALLY DELIBERATE and flag uncertainty. Proceed.
>
>   Step 5: DISCOURSE FEATURE CHECK
>     • Does this form part of an EXTENDED METAPHOR cluster meeting ALL THREE criteria?
>     • Is it HIGH-LEVEL (main predicate) or LOW-LEVEL (modifier)?
>     • Is an MFLAG present or WORDPLAY detected?
>     • Is the conceptual mapping NOVEL?
>
>   Step 5b: FINAL JUDGMENT
>     POTENTIALLY DELIBERATE: Source domain enters situation model (DR) + at least
>       one discourse signal (extended [meeting all three criteria], high-level,
>       mflag, wordplay, or novel).
>     NON-DELIBERATE: IR — lexical disambiguation only; source domain not in scene.
>     WIDLII: Genuine ambiguity — label potentially deliberate, flag for review.
>
>   Step 6: SECOND-PASS REVIEW (mandatory — complete after Steps 1–5b for ALL MRWs)
>     Re-examine every POTENTIALLY DELIBERATE verdict:
>     a. Re-apply the COUNTERFACTUAL TEST: can a non-specialist reader understand
